About Lyrebird

Lyrebird is an open-source Android app (Kotlin, DJI Mobile SDK V5) that runs on a DJI Remote Controller, or a phone tethered to one, and exposes drone telemetry, HTTP control, and WebRTC video over the local Wi-Fi network — no DJI SDK integration required on the ground station side. Multiple Lyrebird instances can run on the same LAN for multi-drone setups.

This page is the video-and-connection testing tool for the GroundStation stack: it discovers Lyrebird phones on the network, watches their telemetry socket, tracks MediaMTX video-path readiness, and plays back each drone's live stream over WHIP/WHEP — so video and connection health can be validated with or without an actual drone attached.

Setup

  1. Connect the host and phones to the same Lyrebird Wi-Fi network.
  2. On each phone, enable wireless ADB if needed, then run adb connect PHONE_IP:5555 from the host.
  3. Launch the Lyrebird app and set a unique drone name such as mini1, mini2, or the aircraft label you want to test.
  4. Start this stack with docker compose -f GroundStation/video_test/compose.yaml up -d --build and open this page.
  5. Use Discover to re-scan. A tile appears for each detected phone; telemetry should turn green before the video path becomes ready.
  6. For drone-free video testing, enable mock video in the Lyrebird Default Layout on each phone — it publishes a bundled clip through the normal WHIP path.

Tabs

Video
Live tile wall of every discovered phone with quick FPS/loss/telemetry stats. Click a tile for full diagnostics.
Health
Correlated phone, sender, MediaMTX, browser, and recovery indicators per drone, with the worst active symptom surfaced first.
Video Charts
Receiver-side WebRTC time series: decoded FPS, bitrate, packet loss, jitter, freezes, jitter-buffer behavior.
Telemetry
The full nested JSON telemetry tree per drone — flight state, phone health, streaming config.
Telemetry Charts
Telemetry-derived time series: battery, satellites, altitude, distance to home, speed, Wi-Fi RSSI.
Settings
Read and change each drone's DJI and app settings (RTH altitude, max height/distance, RC pairing, video source) over HTTP.
HTTP
The full catalog of phone /send/ endpoints (flight control, virtual stick, camera/gimbal, waypoints, sensing) for manual testing.
MAVLink
The same drone read over MAVLink and over HTTP at once, field by field, so a value that disagrees between the two wires is visible rather than inferred.
ROS
Liveness and rates for every topic the ros-monitor container sees from DjiNode, plus phone HTTP reachability.

Logs & troubleshooting

Diagnostics are written on the host under GroundStation/video_test/logs/. Cross-reference those with Android logcat and MediaMTX logs when investigating FPS drops or decode errors.
